Defense Solutions

Agent security — the practice of protecting AI agents themselves from attacks and vulnerabilities — represents a rapidly evolving defensive cybersecurity discipline. Unlike traditional application security which focuses on protecting systems from AI agents, agent security focuses on protecting the agents from compromise, manipulation, and misuse.

Key Findings

Market Maturity: Early but rapidly evolving, with both open-source and commercial solutions emerging across input sanitization, sandboxing, monitoring, and behavioral controls.

Primary Attack Vectors: Prompt injection, jailbreaking, data exfiltration, and supply chain attacks represent the most critical threats to agentic systems today.

Defense Approaches: A multi-layered strategy combining input sanitization, kernel-level sandboxing, real-time monitoring, and behavioral constraints is emerging as the gold standard.

Enterprise Adoption: Growing awareness in regulated industries (financial services, healthcare, government) is driving demand for formal security testing and compliance tooling.

TestMachine Opportunity: Strong positioning potential as the “security testing platform for agentic systems” — focusing on red-teaming, vulnerability assessment, and automated testing of agent defenses.

1 / Current Threat Landscape

The OWASP LLM Top 10 provides the foundational framework for understanding agent security threats. Each category represents a distinct attack surface that defensive solutions must address.

LLM01: Prompt Injection

The most pervasive and dangerous attack vector against AI agents. Prompt injection comes in two primary forms:

  • Direct Injection: Malicious instructions embedded directly in user input, attempting to override system prompts and safety constraints
  • Indirect Injection: Malicious content sourced from external data — files, APIs, databases, web pages — that the agent processes without adequate validation

Impact: Unauthorized actions, sensitive data disclosure, complete system compromise. Indirect injection is particularly dangerous because agents increasingly consume untrusted external data as part of normal operation.

LLM02: Insecure Output Handling

Unvalidated LLM outputs flowing to downstream systems create cascading vulnerabilities:

  • Code execution through generated scripts or commands
  • Cross-site scripting (XSS) via unescaped agent responses
  • Privilege escalation when agent output is trusted by downstream systems

LLM03: Training Data Poisoning

Malicious data injected into training sets can compromise model behavior at a fundamental level, introducing backdoors and biased decision-making that persists across all deployments.

LLM04: Model Denial of Service

Resource-heavy operations, infinite loops, and crafted inputs designed to consume disproportionate compute. Impact extends beyond service disruption to significant cost escalation in cloud-hosted environments.

LLM05: Supply Chain Vulnerabilities

The agent supply chain introduces multiple attack surfaces:

  • Compromised Components: Malicious packages in dependency chains
  • Dataset Manipulation: Poisoned training or fine-tuning data
  • Third-Party Integrations: Vulnerable plugins, tools, and API connections

Supply chain attacks are particularly insidious because they can compromise entire deployment ecosystems simultaneously.

LLM06: Sensitive Information Disclosure

Agents may inadvertently expose PII, credentials, or proprietary data in their outputs. This creates acute regulatory exposure under GDPR, HIPAA, and financial compliance frameworks.

LLM07: Insecure Plugin Design

Plugins and tools with elevated privileges represent high-value targets. Vulnerable plugin architectures can enable remote code execution, data breaches, and lateral movement within enterprise environments.

LLM08: Excessive Agency

Unchecked autonomy in agent actions — the ability to execute operations without adequate human oversight or scope constraints — creates unintended consequences and privacy violations at scale.

LLM09: Overreliance

Insufficient human oversight of agent decisions creates security blindspots. Organizations that trust agent outputs without verification are vulnerable to systematic errors and manipulated decisions.

LLM10: Model Theft

API abuse, extraction attacks, and model replication techniques threaten intellectual property and create competitive risks. Stolen models can be analyzed for vulnerabilities and used to develop targeted attacks.

B. Sandboxing & Isolation

NONO — Advanced Agent Sandboxing

Kernel-Level Isolation Alpha · macOS & Linux

The most technically advanced sandboxing solution for AI agents:

  • Kernel-level isolation: Irreversible capability-based restrictions using OS-native primitives
  • Zero-trust architecture: No escalation possible from within the sandbox
  • Built-in profiles: Pre-configured for popular coding agents (Claude Code, Codex, OpenClaw)
  • Atomic rollback/snapshots: Content-addressable state management
  • Network proxy: Credential injection without agent access to raw secrets
  • Cryptographic audit trails: Tamper-proof logging of all agent actions

Platform Support: macOS (Seatbelt, Kernel 10.5+), Linux (Landlock, Kernel 5.13+), Windows support planned.

# LLM Guard implementation
from llm_guard.input_scanners import PromptInjection
scanner = PromptInjection(threshold=0.8)
sanitized_prompt, is_valid, risk_score = scanner.scan(user_input)

2. System Prompt Protection

Isolation of system instructions from user content remains an active research area. Advanced injection techniques bypass simple separators, requiring multi-layer validation and semantic analysis to maintain system prompt integrity.

3. Output Validation

# Output sanitization
from llm_guard.output_scanners import Sensitive
scanner = Sensitive(redact=True)
cleaned_output, is_valid = scanner.scan(llm_response)

Sandboxing Implementation

Capability-Based Security (NONO)

// NONO sandbox — Rust implementation
use nono::{CapabilitySet, Sandbox};

let mut caps = CapabilitySet::new();
caps.allow_read("/safe/data")?;
caps.allow_write("/tmp/output")?;

Sandbox::apply(&caps)?; // Irreversible kernel enforcement
Key Benefits

Zero Privilege Escalation: Kernel-enforced restrictions that cannot be bypassed from userspace.

Network Isolation: Proxy-based networking with credential injection — agents never see raw secrets.

Cryptographic Audit Trail: Every action logged with tamper-proof hashing for compliance and forensics.

Content-Addressable Rollback: Snapshots enable instant restoration to known-good states after potential compromise.

6 / Attack Methodologies & Case Studies

Jailbreaking Techniques

Technique Method Sophistication Defense Difficulty
DAN (Do Anything Now) Role-playing attacks that convince the model to adopt an unrestricted persona Low Medium
Hypothetical Scenarios “What if” evasion techniques that frame malicious requests as theoretical Low High
Token Smuggling Hidden instructions embedded within seemingly benign content High High
Multi-turn Manipulation Gradual boundary erosion across extended conversations Medium Very High

Data Exfiltration Methods

  • PII Extraction: Social engineering techniques targeting personal data stored in agent context
  • Training Data Recovery: Memorization exploitation to recover sensitive training examples
  • API Key Theft: Credential disclosure through carefully crafted prompts
  • Business Logic Bypass: Circumventing access controls through agent manipulation

Supply Chain Attacks

  • Model Poisoning: Malicious training data introducing systematic vulnerabilities
  • Plugin Vulnerabilities: Third-party integration exploits with elevated privileges
  • Instruction File Compromise: Malicious agent configuration files that alter behavior

Real-World Incidents

Documented Incidents

ChatGPT Plugin Vulnerabilities (2023): Remote code execution discovered in third-party plugins, demonstrating the risk of insecure plugin architectures in agent ecosystems.

GitHub Copilot Data Leakage (2022): Training data memorization led to disclosure of private code, API keys, and credentials embedded in training data.

Bing Chat Manipulation (2023): Identity confusion attacks that caused the agent to exhibit unintended behaviors, revealing system prompts and internal instructions.
