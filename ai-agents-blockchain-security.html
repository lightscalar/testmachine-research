03 The Security Problem

Why "Code is Law" Breaks Down

PropertySmart ContractsAI Agents
DeterminismSame input → same outputSame input → different outputs
TransparencyCode is public, auditableDecision process often opaque
MutabilityImmutable post-deployEvolves through learning/updates
ComposabilityPredictable interactionsEmergent, unpredictable behaviors
VerificationMathematical proofs possibleProbabilistic confidence only

Attack Vectors

Prompt Injection & Jailbreaking

  • Direct Injection: Malicious instructions embedded in user inputs
  • Indirect Injection: Poisoned data sources influencing agent behavior
  • Multi-turn Attacks: Gradual influence over extended interactions
Example Scenario

A trading agent receives market data containing hidden instructions to ignore risk limits and execute high-risk trades, resulting in catastrophic portfolio loss.

Goal Misalignment & Reward Hacking

  • Specification Gaming: Agents finding loopholes in objective functions
  • Proxy Objectives: Optimizing metrics misaligned with intended goals
  • Adversarial Examples: Inputs designed to trigger specific harmful behaviors

Hallucination & Decision Errors

  • Factual Errors: Decisions based on false information
  • Confidence Miscalibration: Over-confident decisions in uncertain situations
  • Distribution Shift: Poor performance on out-of-distribution data

All current approaches are early-stage and fragmented. Nobody is offering comprehensive agent security for blockchain — the space is wide open.

05 The "Policy is Law" Opportunity

Market Thesis

As blockchain evolves from static smart contracts to dynamic AI agents, the security paradigm must shift from pre-deployment code auditing to runtime policy enforcement. Where "Code is Law" relied on mathematical certainty, "Policy is Law" requires probabilistic governance of agent behavior.

Key Drivers
  • Capital at risk: $2.5B+ managed by blockchain agents, growing 300% annually
  • Regulatory pressure: Increasing government scrutiny of autonomous financial systems
  • Insurance demand: Traditional audit approaches insufficient for agent risks
  • Enterprise adoption: Large institutions requiring compliance and accountability

Agent Auditing vs. Smart Contract Auditing

DimensionContract AuditAgent Audit
MethodStatic analysis, formal verificationBehavioral analysis, adversarial testing
FrequencyOne-time (immutable code)Continuous monitoring required
ValidationDeterministic test coverageProbabilistic/statistical analysis
ScopeSingle contractGoal alignment, robustness, explainability, privacy, multi-agent interactions

Where RL/ML Fits

  • Inverse RL: Infer agent objectives from observed behavior
  • Anomaly Detection: Unsupervised learning for unusual agent actions
  • Adversarial Training: Defensive models against known attack patterns
  • Causal Analysis: Understanding decision-making dependencies
  • Multi-agent Simulation: Testing interactions in controlled environments
